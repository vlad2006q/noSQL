# Требования

## Функциональные требования
1. Система должна создавать уникальный идентификатор сессии.
2. Данные сессии должны храниться в Redis Hash.
3. При создании должен назначаться TTL.
4. Система должна возвращать данные активной сессии.
5. Система должна сообщать, активна ли сессия.
6. Система должна продлевать срок жизни сессии.
7. Система должна позволять обновлять дополнительные поля.
8. Система должна удалять сессию при logout или отзыве администратором.
9. Система должна выводить сессии заданного пользователя для демонстрации.

## Нефункциональные требования
1. Операции над одной сессией должны выполняться небольшим числом Redis-команд.
2. Секреты подключения не должны храниться в исходном коде; конфигурация читается из `.env`.
3. Основные операции должны покрываться автоматическими тестами.
4. Демонстрационные данные должны быть синтетическими и не содержать персональных данных.

# ADR-001: Redis Hash для пользовательских сессий

- **Статус:** принято для учебного проекта.
- **Контекст:** требуется быстро хранить небольшие записи сессий, проверять активность и автоматически удалять просроченные данные.
- **Решение:** один ключ `session:<session_id>` на сессию; поля хранятся в Redis Hash; срок жизни задаётся командой `EXPIRE` при создании и обновляется при продлении.
- **Рассмотренные альтернативы:**
  1. SQL-таблица — удобна для сложных связей и долговременной истории, но требует очистки просроченных записей и добавляет нагрузку на БД.
  2. Файлы/память приложения — просты, но неудобны при нескольких экземплярах приложения и не дают надёжного общего хранилища.
  3. Redis String с сериализованным JSON — подходит для целой записи, но для точечного обновления отдельных полей менее удобен.
- **Последствия:** быстрые операции, TTL автоматически удаляет просроченные ключи; данные Redis могут быть эфемерными в зависимости от настроек персистентности. Нужны сетевые ограничения и аутентификация Redis в реальной системе.
